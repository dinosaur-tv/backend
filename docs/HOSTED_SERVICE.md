# Общий сервер для нескольких домов

Один экземпляр обслуживает много независимых домов. Календари, темы, фоны, музыка, команды и устройства принадлежат дому, а не серверу. Убирать ограничение по Telegram ID вручную не нужно и не следует: списка разрешённых больше нет.

## Как это устроено

- **Дом** — единица данных. У него есть владелец, участники, устройства и собственное состояние.
- **Участник** приходит по приглашению владельца: видит общее расписание, управляет экраном, подключает свой календарь.
- **Устройство** (телевизор или телефон без Telegram) получает собственный токен на 365 дней. Общих токенов нет.
- Состояние каждого дома шифруется AES-256-GCM отдельно, с ID дома в качестве AAD: запись одного дома невозможно подставить в другой.
- Каждый запрос проходит проверку членства заново; заголовок `X-Dino-Home-Id` без членства даёт 403.
- Фоны лежат в `data/backgrounds/<ID дома>/`, ссылки подписаны вместе с ID дома.

Хранилище — SQLite (`data/households.sqlite`, режим 0600) с транзакциями на каждую запись.

## Включение открытой регистрации

```dotenv
REGISTRATION_OPEN=true
MAX_HOUSEHOLDS=100
```

`true` — любой человек в Telegram создаёт свой дом. `false` — новые дома не создаются, но приглашения в существующие продолжают работать. `MAX_HOUSEHOLDS` — вместимость сервера: при достижении лимита регистрация отвечает 503, работающие дома не затрагиваются.

Квоты на дом: 5 домов на человека, 8 участников, 16 устройств, 8 активных приглашений, 120 команд в минуту. Ввод кодов ограничен по IP и глобально.

## Перенос существующей установки

При первом запуске состояние `data/state.enc` переносится в дом «Мой дом»: владельцами становятся ID из `TELEGRAM_ALLOWED_USER_IDS`, `DEVICE_TOKEN` и старый ключ телевизора становятся его устройствами, фон копируется. Исходный файл не изменяется.

Задайте `TELEGRAM_ALLOWED_USER_IDS` до первого запуска новой версии, иначе перенос остановится с ошибкой. После переноса переменная ни на что не влияет: добавление ID туда доступа не даёт.

Установка с нуля оставляет `TELEGRAM_ALLOWED_USER_IDS` и `DEVICE_TOKEN` пустыми.

## Обязанности оператора

Открытая регистрация делает вас оператором персональных данных других людей.

- **Google.** Чтобы посторонние подключали свои календари, приложение должно быть опубликовано и пройти верификацию Google: в режиме Testing refresh token живёт 7 дней, а войти могут только Test users. См. [Google Calendar](GOOGLE_CALENDAR.md).
- **Документы.** `/privacy` и `/terms` отдаёт сам сервер — проверьте, что текст соответствует вашей практике и юрисдикции.
- **Данные.** У вас есть административный доступ к хранилищу. Резервные копии храните вместе с `TOKEN_ENCRYPTION_KEY` и удаляйте по своей политике: удаление дома в приложении стирает активные данные, но не ваши бэкапы.
- **Ёмкость.** Один процесс, SQLite и лимиты в памяти. Для большой нагрузки нужны отдельное хранилище и общий счётчик запросов.
- **Аудит.** Тесты изоляции домов есть в `src/multitenant.test.ts` и `src/households.test.ts`, но они не заменяют независимый аудит.

Не уверены в этих обязанностях — держите `REGISTRATION_OPEN=false` и приглашайте людей вручную.
